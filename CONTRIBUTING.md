## 🏗 1. Two-Layer Architecture

The codebase strictly enforces a two-layer separation of concerns:

```
┌────────────────────────────────────────────────────────┐
│                   Xyo.Sdk (Facade)                     │
│  - IXyoClient / XyoClient                              │
│  - Dependency Injection (IServiceCollection)           │
│  - SocketsHttpHandler & Socket Pooling                 │
│  - Memory-Safe Bounded Streaming GZip & Tar Reader     │
│  - Zero-Trust Egress Domain Validation & SSRF Defense  │
│  - RFC 7807 Typed Exception Hierarchy                  │
└───────────────────────────┬────────────────────────────┘
                            │ depends on
┌───────────────────────────▼────────────────────────────┐
│               Xyo.Generated (Transport)                │
│  - OpenAPI C# Contract & Model Definitions             │
│  - System.Text.Json Custom Converters                  │
│  - Machine-generated by OpenAPI Generator (generichost)│
└────────────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **Never modify files inside `src/Xyo.Generated/` manually.** All changes to API contracts, models, or endpoint stubs must originate from the central specification repository (`xyo-financial/specs`).

## 🔀 2. Contribution Workflow & Decision Matrix

| Nature of Change | Target Location | Process |
| :--- | :--- | :--- |
| **API Contract / Endpoint / Schema** | `xyo-financial/specs` | Open PR in specs repository &rarr; triggers automated regeneration workflow in `sdk-dotnet`. |
| **Ergonomics / DI / Streaming / Security** | `src/Xyo.Sdk/` | Open PR in `sdk-dotnet` with accompanying xUnit test coverage. |
| **Bug Fix in Wrapper Logic** | `src/Xyo.Sdk/` | Submit PR with regression unit test in `tests/Xyo.Sdk.Tests/`. |

## ⚙️ 3. Automated & Local Code Generation

### Automated Regeneration (CI/CD)
When an OpenAPI spec is tagged in `xyo-financial/specs`, GitHub Actions dispatches a `spec_tagged` event to `.github/workflows/generate.yml`, regenerating `src/Xyo.Generated/`, running the test suite, and creating a pull request or commit.

### Local Regeneration
To regenerate the client locally against a local checkout of specs:

```bash
make generate
```

- **Node.js:** Node 20+ (for OpenAPI generator CLI)

## 🛡 5. Quality Gates & Validation

Before submitting a Pull Request, ensure all local verification checks pass:

```bash
# Build solution
dotnet build Xyo.Sdk.sln -c Release

# Run test suite with code coverage
dotnet test Xyo.Sdk.sln -c Release --collect:"XPlat Code Coverage"

# Verify code formatting
dotnet format Xyo.Sdk.sln --verify-no-changes
```

Or run via Docker:

```bash
make docker-test
```

## 🧪 6. Development & Testing Guide

- **Unit Tests:** Located in `tests/Xyo.Sdk.Tests/`. Use `MockHttpMessageHandler` to simulate HTTP responses deterministically without requiring a live server.
- **Coverage Target:** Minimum **90% branch and statement coverage** for all files in `src/Xyo.Sdk/`.
- **Security Tests:** Ensure any new URL or header inputs have explicit SSRF, CRLF, and bounded buffer tests.

---

## 🚀 7. Pull Request & Commit Standards

- **Conventional Commits:** Use standard prefixes:
  - `feat(client): add support for bulk batch streaming`
  - `fix(security): sanitize CRLF characters in x-api-user header`
  - `docs(readme): add ASP.NET Core DI example`
  - `test(tar): add decompression bomb test fixture`
- **Branch Naming:** `feat/feature-name`, `fix/issue-description`, `docs/update-policy`.

---

## 📦 8. Release & Versioning Process

The project adheres to [Semantic Versioning 2.0.0](https://semver.org/):
- **Patch (v2.0.x):** Bug fixes, security patches, internal refactorings.
- **Minor (v2.x.0):** Backwards-compatible public API additions.
- **Major (vX.0.0):** Breaking public API changes.

Publishing is triggered automatically when a Git tag adhering to `v[0-9]+.[0-9]+.[0-9]+` is pushed to `main`.
